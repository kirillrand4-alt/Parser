# Документация: Система мониторинга цен конкурентов на компрессорное оборудование

---

## 1. Назначение и архитектура

Система автоматически обходит 6 сайтов конкурентов, извлекает карточки компрессорного оборудования с ценами и техническими характеристиками, сохраняет результаты в CSV и SQLite, и предоставляет веб-интерфейс для управления и просмотра данных.

```
┌─────────────────────────────────────────────────────────┐
│  Веб-интерфейс (webui.py / Flask)                        │
│  ┌──────────────────┐   ┌────────────────────────────┐  │
│  │  Запуск/Стоп     │   │  Проверка URL по списку    │  │
│  │  полного прогона │   │  (prices_checked_*.csv)    │  │
│  └────────┬─────────┘   └────────────────────────────┘  │
└───────────┼─────────────────────────────────────────────┘
            │  subprocess.Popen
            ▼
┌───────────────────────────────────────────────────────────┐
│  monitor/__main__.py (CLI: python -m monitor scrape)       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ...           │
│  │Scraper 1 │  │Scraper 2 │  │Scraper 3 │                 │
│  │(threads) │  │          │  │          │                 │
│  └──────────┘  └──────────┘  └──────────┘                 │
│                     │                                     │
│             HttpClient (кеш + ротация UA + прокси)        │
│                     │                                     │
│             Storage (CSV + SQLite)                        │
└───────────────────────────────────────────────────────────┘
```

### Серверная инфраструктура
- **ОС**: Linux (Selectel VPS, сервер «Alejandra»), но код работает и на Windows
- **Сервис**: `systemd` `parser.service` — автозапуск веб-UI при перезагрузке (`Restart=always`)
- **URL**: веб-интерфейс доступен через nginx по HTTPS; при желании — HTTP Basic авторизация (`WEBUI_USER` / `WEBUI_PASSWORD`)

## 3. Фильтрация нерелевантных товаров

Каждый сайт содержит не только компрессоры. Фильтрация многоуровневая:

### aerocompressors.ru
URL-сегменты второго уровня: разрешены только `kompressori`, `podgotovka-szhatogo-vozduha`, `pnevmoinstrument`, `resivers-vozduhozaborniki`.
Генераторы, строительный инструмент, сварочное оборудование, пескоструйное — отброшены по умолчанию.

### rutector.ru
Фильтр по слагу URL — оставляются только URL, содержащие ключевые слова: `kompressor`, `vintov`, `porshnev`, `pnevmo`, `resiver`, `osushitel`, `vozduh`.

### pnevmo-sklad.ru
Из 91k URL оставляются только те, чей второй путевой сегмент входит в список `COMPRESSOR_SUBCATS` (16 категорий: `vintovye_kompressory`, `osushiteli_vozduha`, `pnevmoinstrument` и т.д.). Региональные поддомены (`novosibirsk.pnevmo-sklad.ru`) канонизируются к `www.pnevmo-sklad.ru`.

### compressortyt.ru
Основной источник — YML-фид: берётся весь каталог целиком, включая газогенерацию (`/stanciya/gazogeneraciya/generatory-azota/`). Явный список категорий (`/stanciya/kompr/vintovye/` и ещё 9) используется только в резервном HTML-режиме, если фид недоступен.

### v-p-k.ru
Единственная категория-точка входа: `/catalog/kompressory/` — сайт уже разделил товары по нужной ветке.

### pnevmoteh.ru
Все URL кроме служебных (блог, доставка, оплата, поиск, корзина) — продукция сайта направлена именно на компрессоры.

## 4. Способы обнаружения и обхода блокировок

### 4.1 Реалистичные заголовки браузера
Каждый запрос отправляется со следующим набором заголовков, имитирующих реальный Chrome:
```
Accept: text/html,application/xhtml+xml,...
Accept-Language: ru-RU,ru;q=0.9,en-US;q=0.8
Sec-Fetch-Dest: document
Sec-Fetch-Mode: navigate
Sec-Fetch-Site: same-origin
Sec-Fetch-User: ?1
sec-ch-ua: "Chromium";v="124", "Google Chrome";v="124"
sec-ch-ua-platform: "Windows"
```
Именно `Sec-Fetch-*` и `sec-ch-ua` отсутствовали бы у типичного скрипта — их наличие убирает блокировки на части WAF (в частности, на pnevmoteh.ru).

### 4.2 Ротация User-Agent
Генерируется пул из ~1000+ строк User-Agent путём комбинирования:
- 8 платформ (Windows 10/11, macOS 13/14, Linux)
- Chrome версий 112–133 (4 варианта build suffix)
- Edge версий 112–133
- Firefox версий 112–133
- несколько строк Safari

**На каждый запрос** выбирается случайная строка из пула — не один фиксированный UA, а реальное разнообразие отпечатков.

### 4.3 Реалистичный Referer
К каждому запросу добавляется `Referer: https://<домен>/` — так запрос выглядит как переход внутри сайта, а не прямой вбив URL.

### 4.4 Вежливые задержки (rate limiting)
Каждый сайт имеет собственный диапазон задержек между запросами (случайный выбор внутри диапазона):

| Сайт | Задержка |
|---|---|
| aerocompressors.ru (DDoS-Guard) | 0.8–1.2 с |
| pnevmo-sklad.ru | 2.0–3.0 с |
| pnevmoteh.ru, rutector.ru, v-p-k.ru | 0.4–0.9 с |
| compressortyt.ru | 0.4–0.9 с |

Задержки переопределяются через env-переменные (`DELAY_MIN`, `DELAY_MIN__PNEVMO_SKLAD_RU` и т.д.) без правки кода.

### 4.5 HTTP-кеш между сессиями
`requests_cache` (SQLite, TTL 6 часов) сохраняет ответы сервера на диск. При перезапуске парсера уже загруженные страницы берутся из кеша — сайт не видит повторных запросов, нагрузка минимальна.

### 4.6 Прокси и пул прокси
Поддерживается SOCKS5/HTTP прокси через переменные окружения (хранятся только в `.runtime_settings.json`, **не в репозитории**):
- `PROXY__PNEVMO_SKLAD_RU=socks5://user:pass@host:port`
- `PROXY_REFRESH__PNEVMO_SKLAD_RU=https://...` — URL для смены IP перед включением

Прокси автоматически активируется при старте, если задана переменная.

**Форматы строки.** Продавцы выдают прокси как `host:port:логин:пароль`, а requests
ждёт `логин:пароль@host:port`. Парсер приводит строку сам (`normalize_proxy`), так что
годятся оба вида; логин и пароль экранируются, если содержат `@` или `:`. Строку, которую
разобрать не удалось, парсер не молча глотает: пишет в лог, что именно не так, и идёт
напрямую, а не падает.

**Схема.** Строка без схемы считается `socks5h://`. Пулы приходят голыми строками
(`логин:пароль@host:port`), и на практике это SOCKS5; если счесть их http, requests шлёт
обычный HTTP-запрос в socks-порт и рукопожатие возвращается как
`BadStatusLine('\x00[\x00...')` — прогон стоит на 0%, а в ошибке нет ни слова ни про
прокси, ни про схему (ловилось ровно так). Именно `socks5h`, а не `socks5`: DNS резолвит
прокси — ради этого резидентный выход и берут против сайта, который режет
датацентр-адреса. Переопределяется `PROXY_SCHEME=http`; явная схема в строке всегда важнее.

**Пул.** `PROXY` / `PROXY__<САЙТ>` принимает не только один прокси, но и список — через
перевод строки, запятую или точку с запятой, либо **путь к файлу** со строкой на прокси:

```
PROXY__PNEVMO_SKLAD_RU=/opt/parser/proxies.txt      # 78 строк socks5
PROXY__V_P_K_RU=socks5://u:p@host1:3001, socks5://u:p@host2:3001
```

Зачем: у pnevmo-sklad 21k+ товарных URL, и один статический выход к концу прогона
упирается в блокировку. Из пула на **каждый запрос** берётся случайный живой прокси.
Подставляется он именно на запрос, а не в общую сессию: при `WORKERS>1` потоки делят одну
сессию, и правка `session.proxies` на лету увела бы запрос одного потока через прокси
другого. Отвалившийся выход вычёркивается поимённо, запрос повторяется через живой, и
только когда мёртв весь пул — переход на прямое соединение (запретить:
`PROXY_FALLBACK_DIRECT=0`). Перебор пула не тратит бюджет повторов запроса.

### 4.7 Обнаружение блокировок и аварийная остановка
HTTP-статусы 403 / 429 / 503 считаются сигналом блокировки. После **12 подряд** заблокированных запросов на одном сайте парсер останавливает этот сайт, сохраняет прогресс, и рекомендует повторный запуск с `RESUME=1` (и с прокси). Другие сайты продолжают работу.

### 4.8 Автоматические повторы
Сетевые ошибки (`ConnectionError`, `Timeout`) повторяются до 4 раз с экспоненциальной задержкой (2 с → 4 с → 8 с → 16 с). HTTP 404 — без повтора (страница удалена).

## 5. Методы извлечения характеристик

Для каждого товара парсер извлекает технические характеристики несколькими способами, применяя их последовательно от точного к резервному.

### 5.1 Структурированная spec-таблица (основной метод)
На большинстве сайтов характеристики лежат в HTML-таблице «метка | значение»:

| Сайт | CSS-селектор |
|---|---|
| aerocompressors.ru | `table.tech tr`, `table.characteristics tr` |
| rutector.ru | `.pump-specifications__item`, `table.zebra tr` |
| pnevmo-sklad.ru | `table.charstable tr`, `.prodbig__chars-table tr` |
| v-p-k.ru | `.properties-group__item` (div-структура) |
| pnevmoteh.ru | `<dl class="clearfix">` (пары `<dt>`/`<dd>`) |
| compressortyt.ru | YML-фид (XML) + HTML-обогащение |

### 5.2 Детектор матрицы сравнения (пропуск серийных страниц)
Некоторые страницы — не карточка конкретного товара, а таблица-сравнение нескольких моделей серии (например, «CompAir L26: варианты L26-7,5 / L26-10 / L26-13»). Такая таблица имеет много столбцов.

**Алгоритм:** если в таблице ≥ 2 строк, где ненулевых ячеек ≥ 4 — это матрица сравнения → страница пропускается (`parse_product` возвращает `None`).

Нормальные таблицы (метка + значение = 2 ячейки; метка + значение + единица = 3 ячейки) проходят без изменений.

### 5.3 Иконочные булевы значения
Ячейки с «да/нет» часто содержат иконку вместо текста (галочка / крестик). `cell_value()` распознаёт:
- символы `✓ ✔ + да есть` → `"да"`
- символы `— – - − ✗ × нет` → `"нет"`
- CSS-классы иконок: `check tick galka icon-yes` → `"да"`, `minus icon-no cross close` → `"нет"`

### 5.4 Тристейт для булевых полей
«Частотный преобразователь», «Осушитель» и аналогичные поля записываются только если явно указаны на странице. Если поля нет на странице — оно остаётся пустым. Это важно для матчера: `""` означает «не известно», `"нет"` означает «точно нет».

### 5.5 Характеристики из пути URL категории (aerocompressors)
Таблицы aerocompressors.ru почти никогда не содержат полей «Привод» и «Частотник» — но эта информация закодирована в сегментах URL:

| Сегмент URL | Поле | Значение |
|---|---|---|
| `s_pryamym_privodom` | Привод | прямой |
| `s_remennym_privodom` | Привод | ременной |
| `chastotn*`, `invertor*`, `reguliruemym_privodom` | Частотный преобразователь | да |
| `s_osushitelem` | Осушитель | да |

Если поле уже есть в таблице — таблица в приоритете. В поле `specs` добавляется маркер `"Источник (из URL категории)": "Привод, Частотный преобразователь"` — матчер знает, что это не данные со страницы, а вывод из категории.

### 5.6 Универсальный резервный сборщик (harvest_specs)
Когда сайт-специфичный парсер дал < 3 характеристик (вероятно, изменился шаблон), запускается универсальный сборщик, который проверяет:
1. Все таблицы на странице (кроме матриц сравнения)
2. `<dl>` / `<dt>` / `<dd>` — списки определений
3. Блоки с CSS-классами `*propert*`, `*charact*`, `*spec*`, `*param*` → пары `name`/`value`
4. Элементы `<li>` с форматом «Название: значение»

### 5.7 YML-фид Яндекс.Маркета (compressortyt)
Compressortyt предоставляет машиночитаемый XML-фид. Парсер разбирает его напрямую: цена, валюта, наличие, категория, бренд, изображение — в одном запросе вместо ~32k HTTP-запросов к страницам.

**Фид — не весь каталог, и характеристик в нём нет.** Два замера на живом сайте (10.08.2026):

| | число |
|---|---:|
| товаров в разделе `/stanciya/kompr/` (обход листинга, 594 страницы) | 17 678 |
| из них есть в YML-фиде | 11 255 |
| **нет в фиде** | **6 510** |

Проверено случайной выборкой 10 пропущенных: все 10 — реальные карточки (Kaeser DSD/DSG,
Kraftmann TAURUS/VEGA, ЗИФ СВЭ, Atmos ST, KraftMachine), отсутствуют и по URL, и по имени.
У 8 из 10 цена «по запросу» — в этом и причина: фид несёт в основном товары с ценой, а
карточки без цены как раз нужны GAP-анализу.

Поэтому по умолчанию работают **оба источника**:
- `COMPRESSORTYT_ENRICH=1` (**по умолчанию включено**) — для каждого товара из фида
  подгружается HTML-страница за характеристиками. Без этого `specs` пустой у 100% карточек
  сайта и матчер по ним работать не может: нет ни кВт, ни бар, ни производительности.
  Страница отдаёт полный паспорт — проверено: 21 характеристика, включая мощность,
  давление, производительность, привод, частотник, осушитель, охлаждение и вес.
- `COMPRESSORTYT_UNION=1` (**по умолчанию включено**) — после фида парсер идёт по каталогу
  и добирает те 6 510 товаров, которых в фиде не было.

Пагинация каталога — `/page-N/` в пути (не `?page=N`: на этот вид сайт отвечает 404), товар
на листинге — тайл `a.product__title-link` с 5 сегментами пути; ссылки на бренды и категории
имеют 3-4 сегмента и товаром не считаются.

## 6. Извлечение ключевых полей

### Цена
**Алгоритм (`clean_price`):**
1. Нормализация пробелов (NBSP ` `, нулевой пробел `​`, тонкий пробел)
2. Регулярное выражение на первый «ценовой токен»: `\d+(?: \d{3})*(?:[.,]\d{1,2})?`
   - Берётся только **первый** найденный — защита от склейки текущей и старой цены из одного DOM-узла
   - Допускается хвост из 1–2 знаков после запятой (копейки), но не 3 знака (это тысяча, не дробная часть)
3. Санитарный диапазон: **100 ₽ – 50 000 000 ₽**. Значение вне диапазона (артикул прочитанный как цена, две цены склеенные в одно число) записывается в `price_raw` для диагностики; поле `price` остаётся пустым.

**Приоритет источников:**
- `[itemprop=price]` → атрибут `content` (машиночитаемое число) — самый надёжный
- Затем CSS-класс `.price`, `.pricebox__price`, `.ui-price-price` и т.п.

### Старая цена / скидка
`old_price` парсится из отдельного элемента (`.price-old`, `.pricebox__oldprice`), и записывается только если **строго больше** текущей цены — иначе `None`. `discount_pct` рассчитывается автоматически.

### Флаг «Цена по запросу» (`price_on_request`)
Если `price = None` и в тексте `availability` есть «запрос» или «заказ» → `price_on_request = 1`. Матчер различает «нет цены потому что сайт не публикует» и «нет цены потому что не распарсилась».

Дополнительно: pnevmo-sklad — если видимый блок `.pricebox` содержит текст «по запросу», числовое значение из DOM игнорируется (защита от утечки устаревшей скрытой цены).

### Бренд
Иерархия источников:
1. Явное поле в таблице характеристик: «Бренд», «Производитель», «Марка», «Торговая марка»
2. Ссылка на страницу бренда (`/brands/`, `/katalog_po_brendam/`)
3. Поиск известного бренда как подстроки в названии товара (список ~50 брендов: Atlas Copco, Kaeser, CompAir, Remeza, Fubag и др.)

### Модель (короткий код)
`extract_model_from_name` убирает из полного названия:
- Бренд
- «шумовые» слова: винтовой, поршневой, спиральный, безмасляный, дизельный, электрический, передвижной, компрессор, станция, привод, ременной и др. (~30 слов)

Результат: «Винтовой компрессор Atlas Copco XATS 487 дизельный» → `"XATS 487"`.

### Статус / наличие
Нормализованные значения `series_status`:
- `"в наличии"` — есть цена и нет негативных сигналов
- `"под заказ"` — явно написано «под заказ», «ожидается», или нет кнопки «купить»
- `"нет в наличии"` — «нет на складе», «распродано», «отсутствует»
- `"снято"` — «снято с производства», «архивный», «выведен из ассортимента» (сканируется по всему тексту страницы)
- `"неизвестно"` — нет никаких сигналов

### Нормализация Unicode
На выходе из каждого парсера:
- Неразрывный дефис U+2011 → ASCII `-` (в ~550 названиях pnevmoteh вида «F11 ‑ 10 бар»)
- Математический минус U+2212 → `-`
- Дефис-тире U+2010 → `-`
- NBSP в числах → обычный пробел (обрабатывается в `clean_price`)
- En-dash `–` и Em-dash `—` **не меняются** (используются для обозначения диапазонов)

## 7. Checkpoint-система (возобновление прерванного прогона)

Для каждого сайта ведётся файл `cache/<site>.checkpoint.json`:
```json
{
  "product_urls": ["https://...", "https://..."],
  "done_urls": ["https://...", "..."],
  "failed_urls": ["https://..."]
}
```

При запуске с `RESUME=1`:
- URL из `done_urls` **пропускаются** — парсинг продолжается с места остановки
- URL из `failed_urls` **повторяются** — часто блокировки снимаются через время или с прокси
- Список `product_urls` берётся из кеша — дорогостоящий обход sitemap/каталога не повторяется
- Каждые 25 товаров прогресс атомарно записывается на диск (через `.tmp` + `rename`)

Дополнительно: при `SEED_DONE_CSV_DIR=/path` ранее сохранённые CSV читаются и их URL добавляются в `done_urls` — перезапуск полного прогона не дублирует уже собранные карточки.

---

## 8. Параллельная работа (WORKERS)

По умолчанию каждый сайт обрабатывается последовательно (1 воркер). Переменная `WORKERS=8` или `WORKERS__RUTECTOR_RU=4` включает параллельные запросы через `ThreadPoolExecutor`. Все 6 сайтов всегда запускаются параллельно друг другу в отдельных потоках.

### Структура поля `specs` (JSON)
Ключи — оригинальные названия характеристик с сайта:
```json
{
  "Мощность, кВт": "7.5",
  "Производительность, л/мин": "900",
  "Давление, бар": "10",
  "Ресивер, л": "270",

  "Осушитель": "нет",

```

Ключ `"Источник (из URL категории)"` — служебный, указывает какие поля выведены из URL, а не прочитаны со страницы.

## 10. Веб-интерфейс

### Страницы и функции

**Главная (/) — управление прогоном:**
- Выбор сайта (один или все 6)
- Кнопка «Запустить» — запускает `python -m monitor scrape` как subprocess
- Кнопка «Остановить» — посылает SIGTERM, затем через 3 с SIGKILL
- Чекбоксы: `RESUME` (продолжить с места остановки), `SHUFFLE` (перемешать URL для тест-прогона)
- Live-лог через SSE (Server-Sent Events) — обновляется в реальном времени без перезагрузки страницы
- Скачать последний CSV

**Проверка цен по URL (/fetch-urls):**
- Загрузка файла со списком URL (до 512 МБ) — например, список URL из собственной базы
- Парсер последовательно проверяет каждый URL и записывает результат в `prices_checked_<date>.csv`
- Live-прогресс через SSE
- Кнопка «Стоп»

**Настройки (/settings):**
- Поля для proxy-строк и других env-переменных
- Сохраняются в `.runtime_settings.json` (gitignored — никогда не попадают в репозиторий)
- Инжектируются в subprocess при каждом запуске

### Дизайн
Два темы:
- **Aurora Glass** (по умолчанию) — тёмный фон, стеклянные карточки, анимированные цветовые сферы
- **Ivory & Gold** — светлый слоновой кости фон, золотые акценты, шрифты Cinzel/Cormorant Garamond

Переключается кнопкой «🌙» в интерфейсе; выбор сохраняется в `localStorage`.

## 11. Алгоритм полного прогона

```
1. Запуск: веб-UI → кнопка «Запустить» → subprocess python -m monitor scrape
2. Для каждого из 6 сайтов (параллельно, в отдельных потоках):
   a. Обнаружение URL (sitemap.xml / YML-фид / пагинация каталога)
   b. Фильтрация нерелевантных URL (по категории, слагу, глубине пути)
   c. Для каждого URL:
      - GET-запрос (из кеша если свежий, иначе с сайта)
      - Задержка (случайная в диапазоне сайта)
      - Парсинг: цена, наличие, бренд, характеристики
      - Проверка матрицы сравнения → пропуск если серийная страница
      - Обогащение specs из URL (aerocompressors)
      - Нормализация: Unicode, валидация цены, флаг price_on_request
      - Запись в CSV + SQLite
   d. Каждые 25 товаров — сохранение checkpoint
3. Завершение: лог «Готово», CSV доступен для скачивания
```

## 12. Диагностический инструмент (diag_fetch.py)

`tools/diag_fetch.py` — инструмент отладки для запуска на сервере:

```bash
# Разобрать конкретный URL и показать все поля
python3 tools/diag_fetch.py fetch aerocompressors.ru https://aerocompressors.ru/...

# Найти URL по фрагменту слага (обход проблемы копирования спецсимволов)
python3 tools/diag_fetch.py find rutector.ru vintovoy-ceccato

# Список доступных сайтов
python3 tools/diag_fetch.py list
```

Выводит: имя, бренд, модель, артикул, цена, old_price, наличие, статус, все характеристики, URL изображения.

## 13. Переменные окружения

| Переменная | Описание | Пример |
|---|---|---|
| `RESUME` | Продолжить прерванный прогон | `1` |
| `SHUFFLE` | Перемешать URL (тест-прогон) | `1` |
| `WORKERS` | Параллельных воркеров на сайт | `4` |
| `WORKERS__RUTECTOR_RU` | Воркеры для конкретного сайта | `8` |
| `DELAY_MIN` / `DELAY_MAX` | Задержка между запросами, сек | `0.5` |
| `PROXY__PNEVMO_SKLAD_RU` | Прокси для сайта: один, список или путь к файлу-пулу | `socks5://u:p@host:port` / `/opt/parser/proxies.txt` |
| `PROXY_FALLBACK_DIRECT` | `0` — не переходить на прямое соединение, когда пул мёртв | `1` |
| `PROXY_REFRESH__...` | URL смены IP прокси | `https://...` |
| `AEROCOMPRESSORS_MAX` | Лимит URL (0 = все) | `500` |
| `RUTECTOR_MAX` | Лимит URL | `200` |
| `COMPRESSORTYT_ENRICH` | HTML-обогащение specs (**вкл. по умолчанию**; `0` — выключить) | `1` |
| `COMPRESSORTYT_UNION` | Добирать каталогом товары, которых нет в фиде (**вкл. по умолчанию**) | `1` |
| `COMPRESSORTYT_HTML` | Только обход каталога, фид не трогать | `1` |
| `COMPRESSORTYT_MAX` | Лимит офферов в YML | `100` |
| `SEED_DONE_CSV_DIR` | Папка с CSV прошлых прогонов (пропуск дублей) | `/data/prev` |
| `CHECKPOINT_DIR` | Папка для checkpoint-файлов | `cache` |
| `HTTP_CACHE_DIR` | Папка для HTTP-кеша | `/tmp/http_cache` |
| `HTTP_RETRY_ATTEMPTS` | Повторов при сетевых ошибках | `3` |
| `MAX_CONSECUTIVE_BLOCKS` | Подряд-блокировок до остановки сайта | `12` |
| `WEBUI_USER` / `WEBUI_PASSWORD` | Basic Auth для веб-UI | `admin` / `secret` |

Хранятся в `.runtime_settings.json` (gitignored). **Прокси-креды никогда не коммитятся в репозиторий.**
