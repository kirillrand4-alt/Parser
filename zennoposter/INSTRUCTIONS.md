# Руководство: регистратор checko.ru на ZennoPoster 7.7.2

Подробно — что где лежит, за что отвечает, что можно править и как при желании
собрать сценарий из кубиков вместо одного блока кода.

---

## 1. Что этот сценарий делает (общая картина)

Один прогон читает CSV со списком аккаунтов и по каждой строке выполняет цепочку:

```
CSV (аккаунт)
  → [профиль/отпечаток]  загрузить сохранённый ИЛИ сгенерировать свежий + чистка куки
  → [прокси]             назначить IP (липкий на аккаунт или из списка), проверить живость
  → [форма checko]       открыть /sign-up, ввести email + пароль + подтверждение, чекбокс, submit
  → [письмо]             дождаться письма от checko, вытащить ссылку активации
  → [активация]          перейти по ссылке, проверить успех
  → [отчёт]              записать статус в accounts_result.csv
```

Итог по каждому аккаунту: `OK` / `PARTIAL` / `FAIL` / `ERROR` / `SKIP` в файле-отчёте.

---

## 2. Файлы проекта

| Файл | Роль |
|------|------|
| `register_checko.cs` | Главный скрипт. Вся логика регистрации + подтверждения. Вставляется в кубик «Свой код». |
| `prepare_google_profile.cs` | Разовая подготовка профиля: ручной вход в Gmail → сохранение профиля. Нужен только для режима `gmail_web`. |
| `register_b2b.cs` | Универсальный вариант для другого B2B-портала (без email-подтверждения). К checko отношения не имеет. |
| `accounts.csv` | Ваши данные (сделать из `accounts.example.csv`). |
| `proxies.txt` | Список прокси (сделать из `proxies.example.txt`), если не задаёте прокси в CSV. |
| `accounts_result.csv` | Отчёт, создаётся скриптом после прогона. |

---

## 3. Базовые понятия ZennoPoster (коротко)

- **Проект (`.xmlz`)** — файл сценария, который открывается в ProjectMaker.
- **Кубик (действие)** — один шаг сценария на схеме. Соединяются стрелками
  (зелёная — успех, красная — ошибка).
- **«Свой код» (CodeCreator)** — кубик с C# внутри. У нас вся логика в нём.
- **instance** — текущий браузер (вкладки, прокси, профиль). Через него делаем
  всё: `instance.ActiveTab.Navigate(...)`, `instance.SetProxy(...)` и т.д.
- **project** — сам проект: переменные, лог. `project.SendInfoToLog(...)`.
- **Профиль** — «личность» браузера: User-Agent, отпечаток (Canvas/WebGL/шрифты),
  куки. В ZennoPoster UA и отпечаток задаются именно через профиль.

> В нашем варианте почти всё делает один кубик «Свой код». Это проще
> поддерживать: правки — в одном месте, в блоке SETTINGS.

## 4. Как собрать и запустить проект (2 способа)

### Способ A — один кубик «Свой код» (рекомендуется)

1. ZennoPoster → **ProjectMaker** → `Создать новый проект`.
2. На схеме ПКМ → **Добавить действие → Свой код** (или кнопка `C#`).
3. Откройте кубик, вставьте всё содержимое `register_checko.cs`, `ОК`.
4. Соедините стрелкой: `Начало` → ваш кубик. (Обычно соединяется само.)
5. Вверху кода настройте блок **SETTINGS** (раздел 5 ниже).
6. `Сохранить проект` — получите свой `.xmlz`.
7. Запуск: кнопка **▶** (в ProjectMaker видно браузер и лог) — для отладки.
   Боевой прогон — из самого ZennoPoster.

### Способ B — из отдельных кубиков (если хотите визуально)

Логику можно разложить по кубикам. Соответствие «блок кода → кубик»:

| Шаг | Кубик ProjectMaker | Что делает |
|-----|--------------------|------------|
| Данные из CSV | «Работа с таблицами» / список (Lists) | построчно берёт email/пароль/прокси |
| Прокси | «Установить прокси» (Get/Set) | `instance.SetProxy` |
| Профиль | «Эмуляция профиля» | генерация UA + отпечатка |
| Открыть форму | «Переход по URL» (Navigate) | открыть `/sign-up` |
| Ввод полей | «Установить значение» (SetValue) на элементе | вписать email/пароль |
| Чекбокс/кнопка | «Действие с элементом → Клик» | согласие + «Зарегистрироваться» |
| Письмо | «Свой код» или почтовый кубик | прочитать письмо, достать ссылку |
| Активация | «Переход по URL» | открыть ссылку из письма |
| Отчёт | «Работа с файлами» | дописать статус |

> Точные названия кубиков в вашей сборке 7.7.2 могут чуть отличаться. Проще
> держать всё в «Свой код», а на кубики разбивать только те шаги, которые
> хотите «пощупать» мышкой. Можно и смешивать: часть кубиками, часть кодом.

## 5. register_checko.cs — блок SETTINGS (что правите чаще всего)

Всё, что нужно менять под себя, собрано вверху файла между
`----- SETTINGS -----`. Ниже — по каждому параметру.

### Пути и адрес

| Параметр | За что отвечает | Когда менять |
|----------|-----------------|--------------|
| `csvPath` | Путь к входному CSV | Всегда — укажите свой файл |
| `resultPath` | Куда писать отчёт | По желанию |
| `regUrl` | Страница регистрации (`https://checko.ru/sign-up`) | Только если checko сменит адрес |

### Селекторы формы (XPath)

Уже проставлены под реальный HTML checko. Менять — только если checko поменяет
вёрстку.

| Параметр | Поле формы |
|----------|-----------|
| `xpOpenSignup` | Кнопка «открыть форму». Пусто `""` — форма сразу на странице |
| `xpEmail` | `//input[@name='user[email]']` — Email |
| `xpPassword` | `//input[@name='user[password]']` — Пароль |
| `xpPassword2` | `//input[@name='user[password_confirmation]']` — Повтор пароля |
| `xpAgree` | `//input[@id='personal_information']` — Чекбокс согласия |
| `xpSubmit` | Кнопка «Зарегистрироваться» |

> **Как получить XPath самому:** запустите проект в ProjectMaker, откройте нужную
> страницу → правый клик по полю → **«Показать в HTML»** → в дереве ПКМ по
> элементу → **«Построить XPath»** → скопируйте. Вставьте в нужный `xp...`.

### Пароль на checko

| Параметр | Значение |
|----------|----------|
| `siteSameAsEmailPassword` | `true` — на checko ставится **пароль от почты** (`email_password`). `false` — отдельный пароль из колонки `password`. |

> Безопаснее `false` (свой пароль на checko). `true` — по вашему запросу, но при
> утечке checko раскроется и почта.

### Чтение письма-подтверждения

| Параметр | За что отвечает |
|----------|-----------------|
| `emailReadMode` | `imap` (по IMAP, надёжно) или `gmail_web` (через браузер в профиле) |
| `imapHost` / `imapPort` | Сервер IMAP (`imap.gmail.com` / `993`) |
| `imapAppPasswordDef` | Пароль приложения по умолчанию, если не задан в CSV |
| `mailFromFilter` | Отправитель для поиска письма (`checko`) |
| `confirmLinkRegex` | Шаблон ссылки активации (уже точный под checko) |
| `mailWaitSeconds` | Сколько всего ждать письмо (сек) |
| `mailPollSeconds` | Как часто проверять ящик (сек) |
| `gmailSearchUrl` | URL поиска в веб-Gmail (для `gmail_web`) |
| `xpGmailFirstMail` | XPath первого письма в списке Gmail (для `gmail_web`) |

### Профиль / отпечаток

| Параметр | За что отвечает |
|----------|-----------------|
| `loadProfile` | Грузить ли профиль из CSV-колонки `profile` |
| `regenProfilePerAccount` | Для аккаунтов без профиля — генерировать свежий профиль (UA+отпечаток) на каждую учётку |

### Прокси

| Параметр | За что отвечает |
|----------|-----------------|
| `proxyListPath` | Файл со списком прокси (fallback). Пусто `""` — без прокси |
| `proxyRequired` | `true` — без живой прокси аккаунт пропускается (`SKIP`); `false` — работаем напрямую |
| `proxyMaxTry` | Сколько прокси перебрать из списка, если очередная мёртвая |

### Прочее

| Параметр | За что отвечает |
|----------|-----------------|
| `sentText` | Подстрока «письмо отправлено» на странице после submit. Пусто `""` — не проверять |
| `xpSuccessMark` / `successText` | Признак успешной активации после перехода по ссылке |
| `typingEmulation` | `true` — посимвольный ввод (человечнее), `false` — вставка целиком |
| `minDelayMs` / `maxDelayMs` | Диапазон случайных пауз между действиями (мс) |

## 6. register_checko.cs — как устроен код (по секциям)

Идёт сверху вниз:

1. **SETTINGS** — параметры (раздел 5).
2. **Хелперы**
   - `pause()` — случайная пауза.
   - `fill(xpath, value, label)` — вписать значение в поле; если поле не найдено
     или xpath пустой — тихо пропускает с предупреждением в лог.
   - `getConfirmLink(...)` — IMAP-клиент: логинится, ищет письмо от checko,
     достаёт ссылку по `confirmLinkRegex`.
   - `getConfirmLinkGmailWeb()` — то же, но через веб-Gmail в профиле.
   - `checkProxyAlive()` — проверка прокси: навигация на `api.ipify.org`,
     сверка, что вернулся валидный IP.
   - `applyNextProxy()` — берёт следующую живую прокси из списка (round-robin).
3. **Загрузка прокси** из `proxies.txt` в список.
4. **Чтение CSV** — заголовок + функция `col(row, "имя")` берёт значение по
   имени колонки (порядок колонок в файле не важен, важны названия).
5. **Главный цикл** по строкам CSV — для каждого аккаунта:
   - выбор пароля (`siteSameAsEmailPassword`);
   - профиль: загрузить сохранённый ИЛИ сгенерировать + `ClearCookie()`;
   - прокси: липкая из колонки `proxy` или из списка;
   - открыть форму, заполнить, отправить;
   - ждать письмо (в выбранном режиме), перейти по ссылке;
   - проверить успех, записать статус.
6. **Запись отчёта** в `resultPath`.

> Логика по каждому аккаунту обёрнута в `try/catch` — ошибка на одной строке не
> роняет весь прогон, аккаунт помечается `ERROR`, идём дальше.

## 7. Формат CSV (accounts.csv)

Разделитель `;`, кодировка UTF-8, первая строка — заголовок. Порядок колонок
любой, важны имена.

| Колонка | Обязательна | Что это |
|---------|-------------|---------|
| `email` | да | Email = логин на checko |
| `email_password` | да (при `siteSameAsEmailPassword=true`) | Пароль от почты; идёт в форму checko |
| `password` | при `siteSameAsEmailPassword=false` | Отдельный пароль на checko |
| `email_app_password` | при `emailReadMode=imap` | Пароль приложения Google для IMAP |
| `profile` | при `emailReadMode=gmail_web` | Путь к сохранённому профилю с сессией Gmail |
| `proxy` | нет | Липкая прокси на аккаунт (иначе берётся из `proxies.txt`) |

Пустую ненужную колонку можно оставить пустой (между `;;`).

---

## 8. Подтверждение почты: imap vs gmail_web

- **`imap`** (рекомендуется). Читает письмо напрямую по IMAP паролём приложения.
  Не нужен вход в браузерный Gmail, работает стабильно.
  Как получить пароль приложения: Google-аккаунт → Безопасность → включить 2FA →
  «Пароли приложений» → 16 символов → в колонку `email_app_password`.
- **`gmail_web`**. Открывает Gmail в **заранее авторизованном профиле** и читает
  письмо из браузера. Профиль готовится один раз через
  `prepare_google_profile.cs` (вход руками). Ломкий: при смене вёрстки Gmail —
  правьте `xpGmailFirstMail`.

## 9. prepare_google_profile.cs (только для gmail_web)

1. Вставьте в отдельный проект/кубик «Свой код», задайте `profilePath`.
2. Запустите в ProjectMaker — откроется браузер.
3. **Войдите в Gmail руками** (логин, пароль, 2FA, капча — всё сами).
4. Скрипт поймает факт входа и сохранит профиль в `profilePath`.
5. Путь пропишите в колонку `profile` нужного аккаунта.

> Автоввод пароля Google и обход его проверок здесь не делается — Google это
> блокирует. Вход выполняете вы, автоматика лишь переиспользует сессию.

---

## 10. Прокси, User-Agent, куки

- **Прокси.** Приоритет: колонка `proxy` (липкая на аккаунт) → список
  `proxies.txt` (round-robin). Липкая **не подменяется** — важно для аккаунтов с
  сессией Gmail (прыжки IP Google считает угоном). Держите за аккаунтом один IP.
- **User-Agent / отпечаток.** Заданы через профиль. Аккаунт с сохранённым
  профилем — UA/отпечаток не трогаются. Без профиля — генерится свежий профиль
  на каждую учётку (`regenProfilePerAccount=true`). Применённый UA виден в логе.
- **Куки.** Между аккаунтами без профиля чистятся (`ClearCookie`), чтобы учётки
  не «склеивались».
- IMAP-подключение к почте идёт **напрямую**, не через прокси.

---

## 11. Частые правки (рецепты)

- **Добавить новое поле формы** (напр. телефон): в SETTINGS завести
  `string xpPhone = "//input[@name='...']";`, а в цикле рядом с другими —
  `fill(xpPhone, col(row,"phone"), "phone");` и добавить колонку `phone` в CSV.
- **Изменить селектор** (checko поменял вёрстку): поправьте нужный `xp...`
  (см. рецепт получения XPath в разделе 5).
- **Замедлить/ускорить**: `minDelayMs` / `maxDelayMs`.
- **Дольше ждать письмо**: увеличьте `mailWaitSeconds`.
- **Отдельный пароль на checko**: `siteSameAsEmailPassword = false` и заполните
  колонку `password`.
- **Без прокси**: `proxyListPath = ""` и `proxyRequired = false`, колонку
  `proxy` не заполнять.
- **Точный текст успешной активации**: после прогона посмотрите страницу, куда
  ведёт ссылка, и впишите слово в `successText`.

## 12. Статусы в отчёте (accounts_result.csv)

| Статус | Значение |
|--------|----------|
| `OK` | Зарегистрирован и почта подтверждена |
| `PARTIAL` | Форма отправлена, ссылка открыта, но признак успеха не совпал (проверьте `successText`) |
| `FAIL` | Письмо не пришло за `mailWaitSeconds` |
| `SKIP` | Пропущен: нет живой/назначенной прокси или нет профиля для gmail_web |
| `ERROR` | Исключение (текст в колонке detail и в логе) |

## 13. Диагностика (если что-то не так)

| Симптом | Причина / что делать |
|---------|----------------------|
| «Поле не найдено» в логе | Сменилась вёрстка checko → обновите `xp...` |
| «Кнопка отправки не найдена» | Поправьте `xpSubmit` |
| Все аккаунты `SKIP` (прокси) | Мёртвые прокси или неверный формат в `proxies.txt`; либо `proxyRequired=false` |
| `IMAP LOGIN не удался` | Нужен **пароль приложения**, а не обычный пароль; проверьте 2FA включена |
| Письмо не находится | Проверьте `mailFromFilter`, увеличьте `mailWaitSeconds`; письмо могло попасть в «Спам» |
| Gmail просит войти (`gmail_web`) | Профиль без сессии → пересоберите `prepare_google_profile.cs` |
| `GenerateNewProfile` ругается | В вашей сборке метод может называться иначе — поставьте перед кодом визуальный кубик «Эмуляция профиля», а строку с генерацией уберите |
| Капча на форме | Скрипт её не решает — добавьте кубик распознавания капчи ZennoPoster перед submit |

---

## 14. Безопасность и назначение

- Инструмент — для регистрации **своих** аккаунтов на своих реальных данных.
  Не для массового создания фейков.
- Одинаковый пароль почты и checko (`siteSameAsEmailPassword=true`) — на ваш
  выбор, но небезопасно; рекомендуется отдельный пароль.
- Вход в Google/Gmail автоматикой не эмулируется — только ручная подготовка
  профиля либо чтение по IMAP.
