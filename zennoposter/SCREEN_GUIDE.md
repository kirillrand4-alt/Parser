# Скрин-гайд: сборка шаблона в ProjectMaker 7.7.2

Пошагово, с привязкой к интерфейсу. Собираем шаблон:
**взять прокси → применить → случайный профиль → зайти на checko.ru → снять API-ключ → сохранить профиль.**

Порядок кубиков (что в итоге должно получиться сверху вниз в дереве действий):

```
1  Свой код C#        →  взять прокси из файла (+удалить строку)     [01_proxy_from_file.cs]
2  Свой код C#        →  применить прокси к браузеру                 [02_set_proxy.cs]
3  (опц.) Свой код C# →  гео/таймзона/язык под прокси                [03_geo_from_proxy.cs]
4  Профиль            →  взять случайный профиль (эмуляция «Высокий»)
5  Браузер            →  переход на https://checko.ru/user/account/api
6  Свой код C#        →  снять API-ключ и сохранить в файл            [05_save_api_key.cs]
7  Свой код C#        →  сохранить профиль в файл                     [04_save_profile.cs]
```

---

## Ориентируемся в окне

По твоему скрину:

- **Верхнее меню:** `Файл · Редактирование · Профиль · Инструменты · Окно · Помощь`.
- **Слева вертикальная вкладка «Действия»** — это тулбокс со всеми кубиками (группы: Браузер, Логика, Данные, Профиль, Работа с файлами, Свой код и т.д.).
- **Центр** — холст с деревом действий (сюда падают кубики).
- **Справа «Браузер»** — окно движка CEF (Chrome), в нём выполняются шаги.
- **Снизу «Лог»** — сообщения выполнения.
- **Слева снизу вкладки** `Переменные` / `Свойства действия`.
- **Ряд иконок внизу** ⚙ 👤 ▦ 🔒 ⊹ — настройки проекта (профиль, защита и пр.).

### Как вообще добавить кубик

Любой из двух способов:

- **A.** Клик по вертикальной вкладке **«Действия»** слева → откроется дерево кубиков → **перетащи** нужный на холст в то место цепочки, где он должен стоять.
- **B.** **Правый клик на холсте** (или на существующем кубике) → **«Добавить новое действие»** → откроется окно выбора с **полем поиска** сверху → вводишь название → выбираешь → «ОК».

> Совет: пользуйся **поиском** в окне добавления — вводишь слово (напр. `код`, `профиль`, `переход`) и сразу видишь нужный кубик. Названия групп в разных сборках чуть отличаются, поиск надёжнее.

## Шаг 0. Файл прокси и (при желании) переменные

1. Рядом с проектом создай папку `data`, в ней `proxies.txt`, вставь свои прокси — по одной на строку (форматы см. в `README.md`).
2. Переменные проекта (`proxy`, `proxyIp`, `apiKey` и т.д.) код создаёт сам при обращении. Если твоя сборка ругнётся «переменная не найдена» — вкладка **«Переменные»** внизу слева → зелёный **`+`** → добавь имя. Список имён есть в комментариях внутри `.cs`.

---

## Шаг 1. Кубик «Свой код C#» — прокси из файла

1. Добавь кубик (способ B) → в поиске набери **`Свой код`** → выбери **«Обработка кода C#» / «Свой код C#»** → ОК.
2. Кубик встанет на холст. Внизу открой вкладку **«Свойства действия»** — там **редактор кода**.
3. Открой файл **`01_proxy_from_file.cs`** (я его прислал), скопируй **всё содержимое** и **вставь** в редактор, полностью заменив то, что там было.
4. Убедись, что тип действия — именно **код C#** (не JS). Обычно есть переключатель языка сверху редактора — должно стоять **C#**.
5. Готово. Кубик кладёт прокси в переменные `proxy`, `proxyIp`, `proxyPort`, ... Если прокси в файле кончились — кубик остановит поток с ошибкой (это правильно, чтобы не работать с реального IP).

> Альтернатива без кода: вкладка **«Списки»** → создать список, привязать к файлу `data\proxies.txt` (галка «синхронизировать с файлом») → кубик **«Взять из списка»** → «Первую строку» + галка **«Удалять взятую строку»** → результат в переменную `proxy`. Тоже потокобезопасно.

---

## Шаг 2. Кубик «Свой код C#» — применить прокси

1. Добавь ещё один **«Свой код C#»** (встанет ниже первого — проверь, что стрелка идёт из кубика 1 в кубик 2).
2. Вставь содержимое **`02_set_proxy.cs`**.
3. Этот кубик делает `instance.SetProxy(...)` — весь трафик браузера пойдёт через прокси.

> Проверить, что прокси реально применился, можно раскомментировав в коде блок с `api.ipify.org` (внизу файла).

---

## Шаг 3 (опционально). Кубик «Свой код C#» — гео под прокси

Нужно для максимальной правдоподобности (таймзона/язык под страну IP).

1. Добавь **«Свой код C#»**, вставь **`03_geo_from_proxy.cs`**.
2. Он определит страну/таймзону/язык по IP и положит в `geoTimezone`, `geoLang`, `geoCountry`.
3. Чтобы применить их к профилю — после кубика 4 (профиль) добавь действия правки профиля: **Профиль → установить часовой пояс** = `{-Variable.geoTimezone-}`, **язык (Accept-Language)** = `{-Variable.geoLang-}`, **WebRTC** = «подменять по прокси». Точные пункты ищи по словам `часовой пояс`, `язык`, `WebRTC` в добавлении действия.

> Если возиться не хочешь — пропусти этот шаг: случайный профиль из шага 4 сам выставит согласованную таймзону. Гео-привязка её лишь уточняет под конкретный IP.

---

## Шаг 4. Кубик «Профиль» — случайный профиль (эмуляция «Высокий»)

Это и есть «максимально правдоподобный профиль» (UA + шрифты + WebGL + экран из реальной базы устройств).

1. **Сначала выстави уровень эмуляции браузера «Высокий».** Ищи это в настройках проекта/браузера: правый клик в окне «Браузер» или **Инструменты → Настройки** → параметр **«Степень эмуляции» / «Уровень эмуляции»** → **Высокий**. (Высокий включает подмену WebGL, Canvas, AudioContext, шрифтов, экрана.)
2. Добавь кубик: в поиске **`профиль`** → выбери **«Взять случайный профиль»** (в разных сборках: «Сгенерировать случайный профиль» / «Эмуляция → Новый профиль») → ОК.
3. В свойствах кубика:
   - включи **«Применить профиль к браузеру / к инстансу»** ✅;
   - в настройках генерации (если есть кнопка ⚙): ОС/браузер — можно оставить `Любой` или сузить до `Windows + Chrome`; шрифты — «согласованные с ОС»; разрешение — «из базы устройств».
4. Поставь этот кубик **до** перехода на сайт (порядок: 1 → 2 → [3] → **4** → 5).

---

## Шаг 5. Кубик «Браузер» — переход на страницу API

1. Добавь кубик: в поиске **`переход`** → **«Переход на страницу» / «Перейти по URL»** → ОК.
2. В свойствах в поле URL впиши:
   ```
   https://checko.ru/user/account/api
   ```
3. ⚠ **Аккаунт должен быть уже залогинен** в текущем профиле, иначе на этой странице не будет ключа. Варианты:
   - загрузить ранее сохранённый профиль checko (кубик «Профиль → Загрузить из файла») **до** перехода;
   - или добавить перед этим шагом кубики логина/регистрации (это отдельная цепочка — скажи, если нужно, распишу).

---

## Шаг 6. Кубик «Свой код C#» — снять и сохранить API-ключ

1. Добавь **«Свой код C#»**, вставь **`05_save_api_key.cs`**.
2. Кубик читает HTML страницы, вытаскивает **API-ключ** (`<div class="code">…</div>`), **тариф** и **e-mail**, и дописывает строку в **`data\api_keys.txt`** (потокобезопасно):
   ```
   email | apiKey | тариф | ip:port
   ```
3. Значения также попадают в переменные `apiKey`, `tariff`, `apiEmail`.

> Без кода: кубик **«Получить элемент»** (CSS-селектор `div.code`, взять `innertext`) → переменная `apiKey`; затем кубик **«Добавить строку в файл»** → `data\api_keys.txt`.

---

## Шаг 7. Кубик «Свой код C#» — сохранить профиль

1. Добавь **«Свой код C#»**, вставь **`04_save_profile.cs`**.
2. Сохраняет fingerprint + cookies в `data\profiles\<uid>.zpprofile` для повторного использования.
3. Если компилятор ругнётся на `SaveProfileToFile` (сигнатура плавает по версиям) — удали код и поставь штатный кубик **«Профиль → Сохранить в файл»**, путь `{-Project.Directory-}\data\profiles\{-Variable.profileFile-}`.

---

## Запуск и проверка

1. **Сохрани проект:** `Файл → Сохранить как…`.
2. **Проверка одного прохода:** кнопка запуска/отладки в ProjectMaker (обычно ▶). Смотри окно **«Лог»** — там мои `SendInfoToLog`: «Взята прокси…», «Гео…», «API-ключ сохранён…».
3. Открой `data\api_keys.txt` — должна появиться строка с ключом.
4. **Много-поточно** запускается уже в самом ZennoPoster (не в ProjectMaker): каждый поток заберёт свою прокси, сгенерит свой профиль, снимет свой ключ.

## Частые грабли

| Симптом | Причина / решение |
|---|---|
| «переменная не найдена» | создай переменную на вкладке «Переменные» (Шаг 0). |
| Пустой `apiKey` / ошибка в кубике 6 | аккаунт не залогинен, либо не догрузилась страница — добавь перед кубиком 6 паузу/ожидание элемента `div.code`. |
| Отпечаток «палится» | не выставлен уровень эмуляции «Высокий» (Шаг 4.1). |
| Прокси не применяется | проверь формат строки в `proxies.txt`; раскомментируй проверку IP в `02_set_proxy.cs`. |
| Код не компилируется | убедись, что язык кубика — **C#**, и вставлено всё содержимое файла целиком. |
